# 用画面讲解，而不是把字排上去

## 最新两项反馈的范围

2026-11-07，用户指出：分镜图标的层级太多；有些段落全是文字也不好。原始截图见 `images/rejected-nested-storyboard.png` 与 `images/rejected-text-only-concepts.png`。这不推翻此前确认的白色面型、深蓝紫、缩小主体和留白；它补充了图标复杂度与视觉讲解能力两项要求。下面方案是供下一次设计使用的建议，**没有新生图，也没有被用户逐项验收**。

## 先定义视觉任务

读完口播，用一句话说出观众要看懂什么，例如“输入的是想法，得到的是画面”，而不是“这一屏有两个词”。然后选择适合的表现机制：

|讲解内容|有用的画面|容易退化的做法|
|---|---|---|
|抽象概念|一个清晰符号或实际结果，使概念有具体对象|把名词做得很大，底下再写定义|
|前后变化|保留可比较的同一对象，让输入变成输出|两块文字卡片之间加装饰箭头|
|操作步骤|对象按语义顺序进入，关系在正确时机建立|一屏只出现三个步骤名|
|四个组成部分|少量简单符号/实际例子＋短标签，当前项被聚焦|四个名词淡入后长时间静止|
|新手困惑|问题对应一个真正相关的对象；可逐问呈现|四个完整问句同时排满屏；或四个无关通用图标|
|作品展示|让真实作品承担解释，标签只做识别|把作品塞成小缩略图，外围堆说明|
|对错/有无对照|同一主体改变一个关键条件，结果能比较|一边“对”一边“错”，差异还要靠口播猜|

图形需要承担意义。问“去掉这枚图标，观众会少理解什么？”如果答案只是“画面没那么空”，图标就是装饰，应换机制或删除。

## 修正案例一：排分镜图标

反例结构：外部圆角面板内有四个小取景框，每个取景框又有山峰、太阳、天空负形。它把一个工具概念画成了多层小界面，在实际视频小尺寸下既密又碎。

下一次可以选择：

- 两张极简实心画格，仅以空隙表现先后；不要每格再画照片。
- 一条简洁的面型胶片轮廓，少量必要负形；不再套外面板。
- 若画格仍太复杂，由 imagegen 换一个更直接的符号，保留“排分镜”短标签，不要求硬画四宫格。

这是形状简化，不是把图标缩得更小、换成细线框、模糊内部纹理或降低透明度。若场景本来在展示真实分镜，应放实际分镜作为主内容，而非拿复杂缩略界面充当小图标。

## 修正案例二：提示词四部分

反例只有“任务、画面描述、参考、约束”四组字。它能列名词，但没有解释对应的工作。

可请 imagegen 设计一组统一的简洁符号：目标/任务标记、照片符号、参考标记、约束锁定符号，各配原本短标签。用顺序和当前项强调形成阅读路径。不要为了图形化再塞进任务清单、示例段落、窗口工具栏和多层面板。

如果抽象符号仍不能解释，可分段演示一次真实提示词结果：当前内容出现、对应参考被使用、限制生效。示例必须来自实际任务或明确标为占位，不编造模型结果。四项不必被强制同时放在一行；布局由 imagegen 判断。

## 纯文字何时仍成立

短标题、章节转场、单句强调、必须准确引用的文字和需要阅读的数值可采用纯字。用户说“有些全是文字不好”不等于每屏必须有图标；不要把片头、警示短句也画成流程图。区别是该镜头的任务是否需要视觉解释，纯字是否已经充分完成任务。

## 压缩时保留意义

删长说明 → 选择更直接的视觉对象 → 减少图标内部层级 → 改变信息出现顺序 → 必要时分屏。不要走“删说明后只剩名词”的捷径，也不要用“配满图标”解决所有内容。

在手机观看大小检查：一眼先看到什么、图标能否辨识、关系是否成立、短标签是否需要靠放大才能读清。自动程序不能替代这一步。
